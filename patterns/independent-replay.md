# 独立replay(producer/verifier分離) — Independent Replay

> **EN:** Any number an agent produces that will drive a decision must be recomputed by an independent implementation that shares no code with the producer. Agreement is required before the number may be cited.

## 解決する問題

AIエージェントに集計・統計・バックテストをやらせると、**もっともらしい数値が高速に大量に出てくる**。その数値が正しいかどうかを、出した本人(同じコード、同じパーサ、同じ前提)に聞いても意味がない。バグ・パース誤り・前提の混入は、同一実装内では自己整合してしまい発見できない。

人間のレビューは規模的に追いつかない。だが「決定に使う数値」だけは、独立した計算経路での再導出一致を機械的に要求できる。

## パターン

1. **producer**: 通常の計算実装。中間生成物(パース済みCSV等)を使ってよい。
2. **verifier**: producerのコード・共有パーサ・中間生成物を**一切importしない**独立実装。生データ(元ファイル)から自前で再導出する。
3. **一致条件**: 決定に使う統計量が許容誤差内で一致するまで、その数値は「引用禁止」。不一致はどちらが正しいか判明するまで両方を疑う。
4. **適用範囲の限定**: すべてに適用すると回らない。「確証格の数値」(資金投入・リリース・対外主張の根拠になる数値)に限定する。

## 実装の要点

- verifierのdocstring冒頭に「producerをimportしない」ことを明記し、レビュー時の検査項目にする
- verifierは生データ(元のzip/PDF/APIレスポンスのスナップショット)から独自のパース・抽出を行う。**中間ファイルの共有は分離を壊す**(パーサのバグが両方に伝播する)
- 比較は機械的に行い、一致・不一致を成果物(scorecard等)に記録する
- 実例では、この分離が実際にパース段の欠陥(ページ検出の誤爆)を確証前に検出している

## エージェント運用での使い方

- 数値を出すタスクとそれを検証するタスクを**別セッション・別コンテキスト**のエージェントに割り当てる。同一コンテキストで「検算して」と言うと、同じ思い込みを再生産しやすい
- verifier側のプロンプトには producer の実装を見せない。仕様(何をどう測るべきか)だけを渡す
- 一致するまで結果を下流(意思決定・記事・レポート)に流さない — [[fail-closed-gates]] と組み合わせる

## 失敗モード

- **なんちゃって分離**: verifierがproducerのユーティリティを「少しだけ」importする。1関数でも共有した時点で、その関数のバグは検出不能になる
- **中間生成物経由の汚染**: 生データではなくproducerのパース結果を検証する。それは「集計の検算」であって「計測の検証」ではない
- **全数適用による形骸化**: 全部にverifierを要求すると省略が常態化する。確証格に限定し、そこは絶対に守る
